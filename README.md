# papilla

[![ci](https://github.com/Redox-openDriver/papilla/actions/workflows/ci.yml/badge.svg)](https://github.com/Redox-openDriver/papilla/actions/workflows/ci.yml)
[![license](https://img.shields.io/badge/license-AGPL--3.0--or--later-blue)](LICENSE)

Fingerprint recognition for image sensors, from tiny 80×80 readers up: its own SIFT, geometric verification of matched
pairs, enrollment that stops by itself, adaptation on confident touches, and encrypted template storage. Pure Rust with
no system dependencies; runs on Linux and Redox OS. It is the matching core of
[elanfp-0c4b](https://github.com/Redox-openDriver/elanfp-0c4b). The documentation below is in Russian.

Библиотека распознавания отпечатков пальцев для сенсоров изображения — от маленьких (80×80) до полноразмерных.
Чистый Rust, без системных зависимостей, работает в Linux и Redox OS.

Драйвер сканера отвечает только за своё устройство: получить кадр и описать сенсор профилем.
Регистрацию, проверку, дообучение, формат шаблонов и их шифрование даёт `papilla` — логика одна для всех сканеров.

## Что внутри
| модуль | что делает |
|---|---|
| `profile` | `Profile` — описание сенсора и правил; проверяется при компиляции |
| `frame` | `Frame` — кадр 8 или 16 бит, необязательная маска области пальца |
| `sift` | детектор SIFT (Lowe, 2004), параметры как в OpenCV |
| `matcher` | `Template` и сравнение в духе [SIGFM](https://github.com/goodix-fp-linux-dev/sigfm) (MIT): тест Лоу, согласованность длин и поворота пар |
| `enroll` | `Enrollment` — регистрация до насыщения, отбраковка чужих касаний |
| `gallery` | `Gallery` — проверка и дообучение на уверенных совпадениях |
| `storage` | двоичный формат галереи с проверкой всех полей |
| `vault` | шифрование AEAD, алгоритм выбирается при сборке |

## Подключение сканера
```rust
use papilla::{Detector, Enrolling, Enrollment, Frame, Matching, Polarity, Profile, Template};

const PROFILE: Profile = Profile {
    name: "elan-04f3-0c4b",
    revision: 1,
    width: 80,
    height: 80,
    dpi: 500,
    polarity: Polarity::RidgesBright,
    detector: Detector::SMALL_SENSOR,
    matching: Matching::VALIDATED,
    enrolling: Enrolling { min_touches: 40, max_touches: 120, streak: 10, confident_score: 48, redundant_score: 300, adapt_limit: 60 },
    accept_score: 24,
}
.validated();

let mut enrollment = Enrollment::new(PROFILE)?;
while !enrollment.is_complete() {
    let pixels: Vec<u8> = read_frame_from_the_sensor();
    let progress = enrollment.add(Template::extract(&PROFILE, &Frame::gray8(80, 80, &pixels)?)?);
}
let (mut gallery, summary) = enrollment.finish()?;
let (verdict, learned) = gallery.verify_adapting(Template::extract(&PROFILE, &frame)?);
```

`validated()` — `const fn`: в константе профиль с параметрами вне допустимых границ не компилируется (в обычном `let` это
паника при запуске, для таких профилей есть `check()`). Проверяются границы каждого параметра и связи между ними:
порог допуска не ниже 16, «уверенное» совпадение не слабее двух порогов, пары точек помещаются в кадр.
Это защита от опечаток и заведомо опасных значений, а не доказательство безопасности: порог для нового сенсора
подтверждается только замерами на его кадрах.

Что настраивается под сенсор:
- **кадр**: размер до 1024×1024, 8 или 16 бит, светлые или тёмные гребни, маска;
- **детектор**: `Detector::SMALL_SENSOR` (увеличение ×2 перед поиском точек) или `LARGE_SENSOR`, предел числа точек;
- **сопоставление**: допуски теста Лоу, длины и поворота;
- **регистрация**: минимум и максимум касаний, длина серии узнанных касаний, границы дообучения;
- **порог допуска** `accept_score` — только по замерам (см. ниже).

`revision` увеличивают при любой смене параметров детектора: галереи другой ревизии отклоняются, палец регистрируют заново.

## Как считается оценка
- Каждая точка шаблона участвует не больше чем в одном совпадении — в том, где расстояние между дескрипторами наименьшее.
  Повторы одного и того же узора в пробе оценку не увеличивают.
- Точные дубликаты особых точек убираются при извлечении (как `removeDuplicatedSorted` в OpenCV) и при чтении старых галерей.
- Точки, которые между двумя касаниями сдвинулись меньше чем на `UNMOVED` (четыре пикселя кадра, 0,2 мм на сенсоре
  500 dpi), уликой не считаются — нигде: ни при регистрации, ни при дообучении, ни при проверке. Палец дважды в одно
  место с такой точностью почти не ложится, а грязь, плёнка и след на сенсоре лежат именно так; рисунок, видимый сквозь
  палец, сдвигается вместе с его гребнями на один-три пикселя и в этот радиус попадает. Цена: касание, которое легло
  ближе четырёх пикселей к сохранённому, этим шаблоном не подтверждается — его узнают соседние шаблоны.
- Кадр, поданный повторно, против своего двойника в галерее получает оценку 0, но остальными шаблонами того же пальца
  узнаётся, как любое касание хозяина: отказывать копиям библиотека не берётся — это стоило бы настоящих касаний.
- Параметры сопоставления вне допустимых границ дают оценку 0, а детектор вне границ не извлекает шаблон вовсе. Допустимо
  только то, что не мягче измеренного ни по одному параметру (`Matching::usable`, `Detector::usable`). Это граница для
  набора в целом: у отдельной пары кадров более строгие параметры изредка дают оценку выше, а не ниже.

## Регистрация и дообучение
- Касание считается подтверждённым, если совпадает хотя бы с одним другим касанием сессии не хуже порога допуска.
  Регистрация завершается, когда подтверждённых касаний не меньше `min_touches` и подряд идёт `streak` уверенно узнанных;
  неподтверждённые касания в галерею не попадают. `finish()` до завершения возвращает ошибку и не уничтожает сессию.
- Проверка согласованности убирает одиночные чужие касания. Она не может доказать, что все касания — один палец:
  разные участки одного пальца на маленьком сенсоре тоже не связаны между собой, а два и больше касаний другого пальца
  подтвердят друг друга. Число несвязанных областей есть в `Summary`.
- Неподвижный рисунок под пальцем. Начиная с двенадцатого касания, касание считается подозрительным, если одних его
  неподвижных точек хватает на допуск против половины прежних касаний или больше: так выглядит регистрация из копий
  одного кадра, рисунок, показанный по очереди в двух местах, и настоящий палец поверх плотного рисунка, который не
  двигается. О подозрительном касании сообщает `Progress::suspect` — драйвер по нему просит сдвинуть палец заметнее.
  На третьем таком касании `add` возвращает `EnrollError::Fixed`, и дальше эта регистрация только отказывает (`add` и
  `finish`): сенсор нужно протереть и начать заново. На записанных сессиях подозрительных касаний нет.
  - Чего правило не видит: рисунок слабее порога допуска (он и оценки не добавляет), рисунок под меньшей частью касаний
    или появившийся во второй половине регистрации, рисунок, показанный по очереди в трёх и более местах, и профили,
    которые заканчивают регистрацию раньше четырнадцати касаний.
  - Обратная сторона, измеренная на искусственных кадрах (48 сессий на строку). Палец, который ложится каждый раз в
    пределах ±0,2 мм, получает отказ всегда, в пределах ±0,25 мм — в 44 % сессий, ±0,3 мм — в 8 %, ±0,36 мм — в 2 %,
    шире — ни разу. Палец, который сползает от касания к касанию шагами около 0,1 мм, — в 38 %, 0,15 мм — в 15 %; при
    шагах от 0,2 мм отказы редки (0–8 %). При том же радиусе и отсчёте с шестого касания сползающий палец получал
    отказ в 69, 44 и 12 % сессий — поэтому отсчёт начинается позже. Близко поставленные касания друг друга и не
    подтверждают, так что такая регистрация ещё и длиннее.
- Дообучение не берёт касание, у которого хотя бы с одним сохранённым шаблоном одних неподвижных точек хватает на
  допуск: почти точный повтор сохранённого касания ничего нового не несёт и не вытесняет полезные шаблоны. Это не
  фильтр от рисунка: касание с рисунком, не лежащее так близко ни к одному сохранённому, выучивается, как любое другое.
- Шаблон, у которого точек больше предела профиля или точки лежат вне его кадра, не принимается ни в регистрацию, ни в
  дообучение, ни в проверку: галерея, которую удалось записать, всегда читается. Размер исходного кадра шаблон не помнит.
- Дообучение принимает касание, только если оно уверенно совпало с шаблоном **исходной регистрации**. Выученные шаблоны
  участвуют в проверке, но не «ручаются» за новые — случайное ложное совпадение не размножается.

## Границы и защита
- Кадр с неверным размером, файл галереи с неверной длиной, числом шаблонов или точек сверх профиля, нечисловыми координатами —
  ошибка, а не паника; разбор проверен на усечённых и случайно испорченных файлах. Целостность файла обеспечивает `vault`,
  сам формат галереи подмену не обнаруживает.
- Время сравнения ограничено пределом числа точек (проба сверх предела не сравнивается); поиск согласованных пар —
  O(n log n) и сверен с перебором. Пары,
  лежащие точно на границе допуска, проверяются поштучно не больше 64 раз на пару — на подобранном вручную наборе это
  занижает оценку, но не даёт одному сравнению длиться секунды.
- Если поток для параллельного сравнения создать нельзя (предел задач у службы), сравнение идёт в текущем потоке.
- Шаблоны, промежуточные изображения, пирамиды, кандидаты в особые точки, рабочие массивы сравнения и закодированная
  галерея затираются при освобождении (`zeroize`), в том числе при раскрутке стека после паники; шифры собраны с
  затиранием ключевых расписаний. `tests/wipe.rs` гоняет извлечение, сравнение и чтение галереи под распределителем
  памяти, который проверяет каждый блок от 512 байт, освобождённый потоком теста. `Frame` и шаблоны в отладочной печати
  показывают только размеры.
- Сообщения об ошибках — ключи и аргументы (`key()`, `args()`), переводы лежат в `locales/` (`papilla::LOCALES`).

## Шифрование шаблонов (`vault`)
Алгоритм выбирается только при сборке, ровно один:

| feature | алгоритм |
|---|---|
| `aes-256-gcm-siv` (по умолчанию) | AES-256-GCM-SIV, устойчив к повтору nonce |
| `xchacha20-poly1305` | XChaCha20-Poly1305 |
| `aes-256-gcm` | AES-256-GCM |

Формат: `PAPV | версия | id алгоритма | nonce | шифртекст+тег`. В проверяемые данные входит контекст вызывающей стороны
(пользователь, имя пальца, сенсор): файл, перенесённый в другой контекст, не расшифруется. Файл другого алгоритма отвергается,
а не пробуется. Хранение ключа — забота драйвера (TPM и т. п.).

## Калибровка порога
`papilla-bench` (feature `bench`) работает со списками `путь.pgm<TAB>палец<TAB>источник`:

| команда | что показывает |
|---|---|
| `verify <N> <list> [чужие]` | регистрация из N кадров, доля неузнанных своих касаний и хвост оценок чужих |
| `pairs <list> [чужие]` | распределение оценок по всем парам кадров разных пальцев |
| `audit <list>` | кадры, похожие на другой палец сильнее, чем на свой (ошибки разметки) |
| `saturate`, `adapt` | подбор правил остановки регистрации и дообучения |

ELAN 04f3:0c4b (80×80), кадры одного владельца (10 пальцев, 1544 кадра) и 120 пальцев из FVC 2000/2002/2004
(вырезки 80×80 из кадров других сенсоров). В FVC2000 базы DB1 и DB2 сняты с одних и тех же пальцев — в списке они объединены.

| замер | результат |
|---|---|
| `verify 100`: 4 галереи по 100 кадров, 15 193 чужие попытки | наибольшая чужая оценка 7; ≥ 8 — ни одной |
| `pairs`: все 19 019 902 пары кадров разных пальцев | ≥ 14 — ни одной; наибольшая 12 (соседние пальцы одной руки, вероятно ошибка разметки), между разными людьми — 8 |
| свои касания, медиана оценки | 172 / 63 / 113 / 635 (указательный, средний, безымянный, большой) |
| не узнано с одного касания при пороге 24 | 15.9 / 38.0 / 29.3 / 21.1 % |

Что из этого следует и что нет. Порог 24 втрое выше наибольшей оценки чужого человека (8) и вдвое выше наибольшей оценки
среди всех пар кадров (12, соседние пальцы одной руки). Но независимых пар «палец — палец» здесь около 480 (4 галереи
против 120 чужих пальцев), из них с того же сенсора около 40, и владелец галерей один: ноль ложных допусков ограничивает
вероятность ложного допуска сверху примерно 0.6 % на пару пальцев (95 %), а не «одним на 19 миллионов». Для строгой
оценки нужны кадры многих людей с этого сенсора. Рабочий конвейер драйвера (настоящая `Enrollment`, дообучение, две
попытки) проверяется отдельно — `elanfp-dataset replay` в [репозитории драйвера](https://github.com/Redox-openDriver/elanfp-0c4b).

Таблица снята до правила о неподвижных точках. Оно только отбрасывает часть совпадений пары, поэтому оценка пары от него
не растёт и чужие максимумы прежние. Рабочий конвейер перемерен с итоговыми правилами (радиус четыре пикселя, остановка
регистрации на неподвижном рисунке, отказ дообучению на повторах): регистрация четырёх пальцев та же, из 913 своих
касаний не узнано 219 — на три больше, чем без правила, из 16 393 чужих принято 0. Радиус выбирался по тем же
записям: два пикселя стоили одного своего касания, три и четыре — трёх, пять — пяти.

Неподвижный рисунок, видимый сквозь палец, измерен двумя способами, и они расходятся.
- На записях в каждый кадр, свой и чужой, подмешан один и тот же чужой кадр (`elanfp-dataset stained` в репозитории
  драйвера; чужие касания — каждый восьмой кадр). При доле 30 и 50 % из 2564 чужих касаний не принято ни одно
  (наибольшая оценка 5), свои не узнаются в 60 и 84 % случаев, при 70 % не регистрируется ни один палец.
- На искусственных кадрах с нарисованными гребнями (независимая проверка) регистрация поверх рисунка при доле 30–50 %
  проходит чаще, чем останавливается (остановлена в 1–7 сессиях из 12, при 60–70 % — в 10–11, при широком разбросе
  постановки — в 0–3), и там, где прошла, чужое касание принимается в 0–0,9 % случаев в зависимости от вида
  загрязнения (всего 18 примерно из 6000, одно выучено; на чистом сенсоре 0 из 2304). Независимый проверяющий на других
  случайных наборах получал до 1,4 %. При радиусе два пикселя в тех же условиях было около 2,4 %.

Настоящее загрязнение сенсора не проверялось, так что вопрос открыт; сенсор перед регистрацией нужно протирать.

Выбор подхода начинался с прототипа на OpenCV (он сопоставлял по-старому и чисел этой таблицы не воспроизводит). AKAZE
и ORB на таких кадрах хуже, SourceAFIS на кадрах 80×80 не работает. Прототипы в репозиторий не входят.

## Перед вторым сенсором
- Нормализация кадра — глобальный минимум и максимум: один залипший или насыщенный пиксель портит контраст, маска в ней
  не учитывается. Для других сенсоров нужна устойчивая нормализация по маске; после неё пороги калибруются заново.
- `papilla-bench` жёстко работает с 8-битными кадрами и двумя наборами параметров детектора; калибровка по произвольному
  профилю и через настоящую `Enrollment` пока есть только в драйвере ELAN.
- `Matching::VALIDATED` и `Detector::SMALL_SENSOR` подтверждены данными одного сенсора; `Detector::LARGE_SENSOR` не измерен
  вовсе. Границы допустимых параметров привязаны к этим значениям: другому сенсору нужны свои замеры и свои границы.
- Правило остановки регистрации — `streak` уверенных касаний подряд при не меньше чем `min_touches` подтверждённых: на
  двух записанных пальцах из четырёх оно не сработало ни разу, и регистрация шла до предела в 120 касаний. Окно «k из n»
  и остановка по одному минимуму перемерены на тех же записях: регистрация короче (43–83 касания), но неузнанных с
  первого касания заметно больше — 36 % вместо 15 у указательного, 47–57 % вместо 38 у среднего. Правило оставлено.
- Порог неподвижности точки (`UNMOVED`) задан в пикселях кадра, а не в долях миллиметра: для сенсора с другим разрешением
  его нужно пересчитать и перемерить, во что он обходится своим касаниям. Пороги остановки регистрации из-за
  неподвижного рисунка (с двенадцатого касания, половина прежних, три подозрительных) выбраны по тем же записям и по
  искусственным кадрам. Порог в четверть останавливал больше загрязнённых регистраций, но отказывал честному пальцу с
  разбросом ±0,3 мм в 11 сессиях из 12 против одной. Отдельное правило о копиях одного прежнего касания при радиусе
  четыре пикселя отказывало честному пальцу с разбросом в две трети миллиметра в каждой четвёртой сессии.
- Результат зависит от математической библиотеки платформы (`exp`, `atan2`, `powf`): побитовое совпадение шаблонов между
  платформами не обещано и не проверялось.

## Что не входит
Защита от муляжей (liveness), склейка кадров протяжных сенсоров, сенсоры со сравнением на чипе.

papilla = { git = "https://github.com/Redox-openDriver/papilla", tag = "v0.1.0" }

## Источники

- D. G. Lowe, «Distinctive Image Features from Scale-Invariant Keypoints», IJCV, 2004 — детектор и описатель SIFT
  (патент US 6 711 293 истёк в 2020 году). Параметры детектора совпадают с реализацией в
  [OpenCV](https://github.com/opencv/opencv) (Apache-2.0), по которой сверялись результаты.
- [SIGFM](https://github.com/goodix-fp-linux-dev/sigfm) (MIT, © 2022 Goodix Fingerprint Linux Development) — подход
  к сопоставлению для маленьких сенсоров: тест Лоу и согласованность длин и поворотов пар.
- Замеры: кадры владельца с ELAN 04f3:0c4b и вырезки из баз FVC 2000/2002/2004. Сами кадры в репозиторий не входят.
